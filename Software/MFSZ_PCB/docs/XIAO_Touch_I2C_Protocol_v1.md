# XIAO 触摸展板 I2C 协议 V1

本文件为从机固件 V1 的实现约定，对应工程中的 `include/TouchProtocol.h` 和 `src/main.cpp`。软件及实机验证说明见工程 README。可选 IRQ 不默认启用。

交互目标：铜皮按键按下后，从机立即按本地消抖结果点亮对应 WS2812，并保存事件供主机读取；没有触摸时，主机也能选择设备并下发命令点亮对应 WS2812。触摸反馈和主机选中始终并行，不使用互斥的本地/主机灯控模式。

## 1. 总线与编号

| 项目 | 定义 |
|---|---|
| 主机 | 外部屏幕或控制器 |
| 从机 | 本触摸展板的 XIAO ESP32S3 Plus |
| 从机地址 | 7 位地址 `0x42` |
| SDA / SCL | D9/GPIO8 / D10/GPIO9 |
| 建议速率 | 100 kHz |
| 电平 | 3.3 V，上拉及共地由硬件保证 |
| KEY_ID | K 编号本身：K0–K8=`0x00`–`0x08`；K10–K18=`0x0A`–`0x12` |
| 无效编号 | `0x09`、`0x13`–`0xFE`；`0xFF` 专用于表示没有事件 |

全文示例均为十六进制字节，K17 的 KEY_ID 是 `0x11`。主机维护 KEY_ID 与具体 XIAO 型号的对应表，灯控不传型号字符串。S 型 WS2812 映射由从机维护，主机始终使用 K 编号：K18→WS1，K17→WS2，K10→WS9，K8→WS10，K0→WS18。

名称说明：本次输入表中的 `XIAO R2350`、`XIAO RAM41` 按此前项目型号统一写为 `XIAO RP2350`、`XIAO RA4M1`。仅规范显示名称，不改变 K4、K7 的编号或连接。K15 按本次清单使用 `XIAO nRF52840 Plus`。

主机根据这张表把 KEY_ID 关联到型号名称、图片和展示参数。屏幕排序、厂商分组或灯珠串接顺序变化，不应导致 KEY_ID 自动重排。本板没有 K9，后续编号保留空位，不压缩为连续的 0–17。

例如：主机读到 KEY_ID=`0x11` 的 DOWN 事件，即识别为 **XIAO nRF54LM20A Sense**；主机在屏幕上选择 **XIAO ESP32S3 Sense** 时，下发 `10 0D`，从机选中 K13 并点亮 WS6。

I2C 传输由主机发起。从机触摸后先保存事件，主机轮询读取，或收到可选 IRQ 提示后读取。从机不自行发起 I2C 写事务。

## 2. 事务格式

- 读寄存器：主机先向 `0x42` 写入一个寄存器地址字节并结束写事务，再从 `0x42` 读取规定数量的字节。
- 写命令：一次写事务包含完整的 `CMD + 参数`，每个命令长度固定，不跨事务拼包。
- 每次读事务从所选寄存器的第 0 字节开始；无自动地址递增。不能用多次单字节读代替一次四字节读。
- 上电读指针默认为 `0x00`。有效读寄存器地址只切换读指针，不改变事件或 RGB。
- 所有多字节整数均为小端序。
- I2C 电气 ACK 只说明字节被总线接收，命令接收及参数校验结果通过 STATUS.RESULT 查询。

## 3. 寄存器与命令表

| 地址/命令 | 方向 | 数据长度（不含地址/命令字节） | 定义 |
|---|---|---:|---|
| `0x00` STATUS | 读 | 4 | VERSION、FLAGS、EVENT_COUNT、RESULT |
| `0x01` EVENT_HEAD | 读 | 4 | ACTION、KEY_ID、SEQ_L、SEQ_H；只查看队首事件 |
| `0x02` KEY_STATE | 读 | 4 | 当前消抖触摸状态位图，bit n 对应 Kn |
| `0x10` SELECT_DEVICE | 写 | 1 | KEY_ID；清除其他主机选中项，选中目标并指定 Seeed 绿 |
| `0x11` SET_RGB | 写 | 4 | KEY_ID、R、G、B；设置该设备的主机选中色，保留其他选中项；RGB 全 0 表示取消该项 |
| `0x12` CLEAR_SELECTION | 写 | 0 | 清除全部主机选中项；正在触摸的灯仍保持触摸反馈 |
| `0x13` | 保留 | — | V1 不定义模式切换命令 |
| `0x20` ACK_EVENT | 写 | 2 | SEQ_L、SEQ_H；确认队首事件，匹配时移除一条 |
| `0x21` CLEAR_EVENTS | 写 | 0 | 清空事件队列与溢出标志，不重置事件序号计数器 |

### STATUS：四字节

| 字节 | 字段 | 定义 |
|---|---|---|
| 0 | VERSION | V1 固定为 `01` |
| 1 | FLAGS | bit0=READY；bit1=有待处理事件；bit2=队列发生溢出；bit3=存在主机选中项；bit4=RGB 驱动故障；其余为 0 |
| 2 | EVENT_COUNT | 当前队列内事件数，0–32 |
| 3 | RESULT | 最近一条写命令的接收及校验结果；读寄存器操作不覆盖该结果 |

RESULT：`00`=校验通过、已接收，`01`=未知地址/命令，`02`=长度错误，`03`=KEY_ID 或参数无效，`04`=事件确认序号不匹配，`05`=触摸系统尚未就绪，`06`=RGB 驱动已处于故障状态。校验失败时不执行命令，不修改灯或队列。RGB 命令接收时按顺序更新期望灯态，实际灯链刷新放在主循环中完成；`00` 不代表已经检测到灯珠发光。READY=0 时允许读取状态，KEY_STATE 暂为 0、EVENT_HEAD 为无事件；主机应等 READY=1 后开始业务交互。

### EVENT_HEAD：四字节

| 字节 | 字段 | 定义 |
|---|---|---|
| 0 | ACTION | `01`=DOWN 按下；`00`=UP 松开；`FF`=无事件 |
| 1 | KEY_ID | 对应 K 编号；无事件时为 `FF` |
| 2 | SEQ_L | 16 位事件序号低字节 |
| 3 | SEQ_H | 16 位事件序号高字节 |

空队列返回 `FF FF 00 00`。序号从 1 开始，仅在事件成功入队时递增，`FFFF` 后回到 `0000`。空队列与序号为 0 的有效事件通过 ACTION 区分。

### KEY_STATE：四字节

低字节先返回，合成 `uint32_t` 后，bit n=Kn，1=消抖确认按住，0=松开。bit9 和 bit19–31 固定为 0。此处使用 K 编号，不使用 WS2812 的链路序号。

示例：K17 按住=`00 00 02 00`；K0 与 K17 同时按住=`01 00 02 00`。

## 4. 事件队列规则

1. 采用深度为 32 条的 FIFO，按下和松开都经消抖后入队；持续按住只生成一次 DOWN，松开只生成一次 UP。
2. 同一轮扫描内发生多个变化时按 KEY_ID 从小到大入队，保留多键变化。物理先后若小于采样分辨率，不宣称能区分先后。
3. 读取 EVENT_HEAD 不出队。读失败或想重试时，再读仍返回同一事件。
4. 主机处理后写 `20 SEQ_L SEQ_H`。只有与当前队首序号匹配时才移除一条；重复确认最近已确认的序号返回成功，但不移除下一条。其他序号不匹配时返回 RESULT=`04`。
5. 即使业务只关心 DOWN，主机也应读取并确认 UP，避免队列被松开事件阻塞。
6. 队列满时保留现有队列、丢弃新事件，并置 FLAGS.bit2。溢出后不能宣称事件完整；主机应执行 CLEAR_EVENTS，再读取 KEY_STATE 恢复当前按键状态。随后按序处理新事件。
7. 每次从机重启，队列、序号和状态均重新初始化。主机发现从机重启后应丢弃旧的未完成确认，重新等待 READY 并读取 KEY_STATE。

## 5. RGB 控制规则

从机分别维护 touchMask（当前消抖触摸状态）和 hostSelectedMask（主机选中状态）。对于每个 K，对应 WS2812 是否亮起由两者逻辑或决定，不需要切换模式。

| 当前被触摸 | 主机选中 | 最终灯光 |
|---|---|---|
| 否 | 否 | 熄灭 |
| 是 | 否 | Seeed 绿 |
| 否 | 是 | 主机指定颜色，SELECT_DEVICE 默认 Seeed 绿 |
| 是 | 是 | 触摸反馈优先显示 Seeed 绿，松开后恢复主机指定颜色 |

- 上电 hostSelectedMask 为空，触摸扫描确认按下后立即本地点亮对应灯，无需等待主机读取或回传指令；同时生成 DOWN 事件。
- 松开后生成 UP 事件。该设备没有被主机选中时熄灭；已经被主机选中时继续显示选中色，直到主机取消或更换选择。
- SELECT_DEVICE 只清除其他主机选中状态，不清除 touchMask。其他仍被手指按住的灯继续亮起。
- SET_RGB 只改变该设备的主机选中色，保留其他主机选中项，适合同时对比多个设备。R/G/B 每项为 0–255，经过统一亮度缩放，初始亮度约为 64/255。
- SET_RGB 的 RGB 全 0 表示取消该设备的主机选中状态；若该键仍被触摸，灯继续显示触摸反馈。
- CLEAR_SELECTION 只清除主机选择。无人触摸时全部熄灭；存在触摸时只保留被触摸设备的绿灯。
- SELECT_DEVICE 的基础色为 `#8FC31F`，即 R=`8F`、G=`C3`、B=`1F`。
- 主机下发灯控命令不产生按键事件，避免“触摸→主机回传点灯→再次上报按键”的循环。
- 板载用户 LED 只反映“是否存在触摸”，不因主机选中设备而点亮。

## 6. 完整交互示例

以下 `W[...]` 是向从机 0x42 写入的字节；`R[4]` 是主机从 0x42 读取四字节。I2C 地址不包含在方括号中。

### 按下 K17：XIAO nRF54LM20A Sense

1. K17 消抖确认按下，从机立即点亮 WS2，并入队序号 1 的 DOWN 事件。两项都不依赖主机回传。
2. 主机 `W[00]`、`R[4]` 读取 STATUS，发现 EVENT_COUNT>0。
3. 主机 `W[01]`、`R[4]`，返回 `01 11 01 00`：DOWN、K17、序号 1。
4. 主机按 K17/KEY_ID=`0x11` 查询映射表，识别为 XIAO nRF54LM20A Sense 并更新屏幕；按该事件序号保证业务处理不重复。
5. 主机 `W[20 01 00]` 确认事件。若确认丢失，重读和重复确认均不应造成重复业务动作。
6. 如果主机希望屏幕选中状态在松手后保留，可额外发送 `W[10 11]`，从机将 K17 标记为主机选中；触摸灯光仍持续有效。
7. K17 松开时产生 `00 11 02 00`；主机读出后 `W[20 02 00]` 确认。如果执行了第 6 步，WS2 保持选中绿灯；未执行则随松开熄灭。

### 没有触摸时，在屏幕上选择 XIAO SAMD21（K0）

1. 主机发 `W[10 00]`。
2. 从机清除其他主机选中项，选中 K0，对应 WS18 亮 Seeed 绿，不需要按住铜皮焊盘。
3. 若用户此时又触摸 K17，WS18 保留选中灯，WS2 同时亮触摸绿灯，并生成 K17 的 DOWN 事件。
4. K17 松开后 WS2 熄灭，WS18 继续保持选中灯。

### 同时高亮 XIAO nRF54LM20A Sense（K17）和 XIAO SAMD21（K0）

```text
W[12]                清除主机选中项，保留当前触摸反馈
W[11 11 8F C3 1F]    XIAO nRF54LM20A Sense，K17 / WS2 显示绿色
W[11 00 8F C3 1F]    XIAO SAMD21，K0 / WS18 显示绿色，保留 K17
```

### 取消屏幕选择，只保留触摸反馈

```text
W[12]
```

## 7. 主机取事件的方式

默认无需增加硬件：主机每 10–20 ms 读取 STATUS；有事件时循环读取 EVENT_HEAD、处理并确认，直到队列空。队列在未溢出的前提下保留两次轮询之间已发生并结束的短按。

可选增加一根 IRQ：如果 D8/EXT_IO1 未被其他功能占用且已接到主机 GPIO，可定义为开漏、低有效，有待处理事件时拉低，队列清空后释放。主机应按电平检查并读取到队列空，不能只依赖一次下降沿。IRQ 仅通知主机发起 I2C 读取，不传输事件数据。该引脚当前可用性和物理接线需另行确认。
